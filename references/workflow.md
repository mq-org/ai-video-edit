# 動画編集ワークフロー

## 0. 最初に作りたい動画を確認する

素材を受け取ったら、ユーザーが既に伝えた内容を整理する。分かっていることを聞き直さず、不足情報を**3〜5問程度にまとめて**ヒアリングする。専門用語の入力を求めるより、具体的な選択肢と推奨値を示す。

質問例：

1. **何のための動画ですか？** 誰に、どこで見てもらう予定か。講座の本編、インタビュー、SNS向けなど。
2. **何を何本作りますか？** 1本に整える／見どころを複数本／指定区間だけ。長さの希望、説明の順序を保つか、要約・再構成してよいか。
3. **見た目はどうしますか？** 元の画面比率／横／縦／正方形、シンプル字幕／テレビ風テロップ／字幕なし。参考があれば受け取る。
4. **どこまでカットしますか？** 長い沈黙だけ／言い直しも整理／テンポを強める。必ず残す説明、実演、笑いの間、削除したい箇所、名前の正しい表記も確認する。
5. **素材と納品の条件は？** 素材の場所、字幕ファイルの要否、保存先、プレビュー確認か全工程を任せるか。文字起こしが必要ならローカル処理とAPI送信の選択を説明する。

すべてを毎回聞く必要はない。たとえば「講座を横のまま1本、説明を省かず、言い直しだけ削除」と指定されていれば、その内容を採用する。「いい感じに」「お任せ」だけの場合も、**1本か複数本か、内容を短縮してよいか**は成果物を大きく変えるため、推奨案を提示して確認する。

### 迷った場合に提案する既定値

- 1本仕上げ：元の順序と画面比率を保つ。目標尺を無理に決めず、明らかな言い直しと不要な間を整理。白文字＋黒い縁取りの字幕。1素材→1本。
- ショート：9:16・1080×1920。1本30〜90秒を目安に、結論まで意味が通る単位を選ぶ。本数は素材の内容と希望から提案する。
- 字幕は発言に忠実に。名前や専門用語を訂正し、冗長な相づちの省略は意味を変えない範囲に留める。
- 納品先：リポジトリ内の `output/<name>/`。別の場所を指定されたらそこへ保存する。
- 初回は15〜30秒程度のプレビューを確認してから全編を作る。Type-Tのショートでは代表の1本を先に試作してよい。「全工程お任せ」なら待たずに進めてよい。

合意した条件と任された範囲を `data/projects/<name>/brief.md` に保存する。希望と実装に差があれば、制作前に差と代替案を伝える。

## 1. 素材と環境を確認する

1. `scripts/check_env.py` で利用可能な道具を確認する。セットアップが必要なら、その環境に適した手順を案内・実行する。
2. 元動画を保全し、`data/source/` に作業用コピーを置くか、読み取り元として参照する。未許可の外部アップロードをしない。
3. ffprobeで尺・解像度・フレームレート・音声の有無を確認する。映像は全編を一定間隔でサンプリングし、途中の画面切替や画面共有も把握する。
4. 音声を左右それぞれ確認し、片側だけの収録、極端な音量差、雑音を記録する。無音検出の閾値は素材に合わせる。
5. 同じ素材を既に処理していれば、既存の文字起こしと計画を再利用できるか確認する。

素材のURLから取得する場合は、利用者が扱う権限を持つ素材を対象とする。取得したファイルや字幕・チャットも制作データとしてGit管理外に保存する。

## 2. 文字起こしと内容分析

```bash
python3 scripts/transcribe.py data/source/input.mp4 data/transcripts/demo \
  --engine local --prompt "収録の説明と、正しい人名・専門用語を句読点付きで記載する。"
```

- ローカル処理はApple Siliconとmlx-whisperを使う。APIを明示的に選んだ場合のみ `--engine api` を使う。
- `whisper_verbose.json` を一次データとして、全文の `whisper_segments.txt` と語時刻の `whisper_words.txt` を確認する。既存の互換JSONも使える。
- 元動画の長さ、文字起こしがカバーする範囲、長い欠落を照合する。字幕がない区間を、そのまま無音や不要区間と見なさない。
- 内容は全文を読み、話の構成、言い直し候補、残す実演、ショート候補などを用途に合わせて整理する。
- 同音異義語・固有名詞は文脈で確認し、確信がなければユーザーへ確認する。推測で意味を変更しない。案件用語集は `data/projects/<name>/glossary.tsv` に保存する。

## 3A. 1素材を1本に整える

### 下書きを作る

```bash
python3 scripts/plan_edit.py data/source/input.mp4 \
  data/transcripts/demo/whisper_verbose.json \
  --out data/projects/demo/edit.json --min-silence 0.8 --keep-silence 0.2
```

無音検出と単語タイムスタンプを照合して、編集計画の下書きを作る。指定値は候補抽出の出発点であり、すべての素材へ機械的に適用する正解ではない。

### AIまたは人が編集計画をレビューする

- 言い間違い・重複・言い直しは全文の意味と照合して判断する。後半の言い直しだけで意味が通るときに前半を削り、削除理由を記録する。
- 無音候補の前後を確認する。スライドを読む時間、実演、余韻、質問への考え中などは残す。
- `segments` に採用区間を元素材時刻で記す。既定は元の順序。並べ替えは要望に含まれる場合だけ行い、因果関係や発言の意味を変えない。
- 字幕の文字とタイミングを確認する。`captions` を省略すると `transcript.words` から自動生成される。自動字幕が不自然なら `captions` を明示し、区切りと文言を直す。指定時刻は元素材の時刻。
- `video`、`subtitle`、`audio` と出力先をヒアリング内容へ合わせる。長尺用の計画にショートの90秒上限を持ち込まない。字幕の別ファイル納品は `subtitle.enabled: true` と `subtitle.burn_in: false`、字幕自体が不要なら `subtitle.enabled: false` にする。
- 削除した区間と理由は計画の `removed`（`start` / `end` / `reason`）へ記録し、判断に迷った箇所や説明は `data/projects/<name>/edit-notes.md` に残す。
- 確認を終えたら `reviewed: true` にする。`check` が通ることだけで、内容のレビューを代替しない。

`source` / `transcript` / `output` のパスは計画JSONのあるディレクトリから解決する。計画を別の場所へ移す場合はパスも確認する。

`removed` は監査用のメモで、採用区間の一次情報は `segments`。削除方針を変更した場合は両者を整合させる。無音短縮を使わず全編を採用する下書きは `plan_edit.py ... --no-silence` で作れる。音声のない映像でもこの指定を使い、字幕は必要に応じて明示する。完成先は `--output` で指定できる。既存の計画を再生成で消さず、別名にする。

```bash
python3 scripts/edit_video.py data/projects/demo/edit.json check
python3 scripts/edit_video.py data/projects/demo/edit.json render --preview-seconds 15
```

プレビューで見た目・テンポを確認する。無音ばかりの冒頭だけを見て判断しない。最初の15秒で字幕やカットが見られない場合は、代表的な区間を使うプレビュー専用計画を作り、元計画を保持する。

プレビューの出力名は完成品のstemに `.preview.mp4` を付けたもの。SRT・ASS・JSONレポートも出力される。既存ファイルを置き換える依頼なら `--overwrite` を指定できる。依頼範囲外の既存動画を消して書き出しを通さない。

```bash
python3 scripts/edit_video.py data/projects/demo/edit.json render
```

## 3B. 複数のショートを作る

1. 単独で意味が通り、興味を引く話を選ぶ。実演・驚き・普遍的な悩み・気づきなどを優先するが、用途に合わない煽りを加えない。チャットがあれば反応も参考にする。
2. `data/projects/<name>/clip-plan.md` に候補、採用理由、不採用理由、予定尺を記録する。本数を満たすために同じ内容を重複させない。
3. `examples/shorts.py` を基にローカルのspecを作る。`SRC`、`WHISPER`、`OUT_DIR`、`LAYOUTS`、`CLIPS` を設定する。クロップはその素材の画面に合わせ、サンプルの数値を無条件に使わない。
4. 元素材の秒数でカット区間とテロップを書き、語の前後に余裕を置く。カット点の調整は `seams.py` が行うが、語欠けの最終確認を省かない。
5. テロップをフレーズ単位に整え、色と強調を付ける。タイトルは全編表示が標準。派手な演出を希望しない場合は、1本仕上げの仕組みで区間ごとにシンプル字幕の計画を作る。
6. 確認済みのspecは `REVIEWED = True` にする。`AUDIO_CHANNEL` は `auto` / `left` / `right` / `stereo` から素材に合わせて指定できる。

```bash
python3 scripts/typet_shorts.py data/projects/demo/shorts.py words
python3 scripts/typet_shorts.py data/projects/demo/shorts.py ass
python3 scripts/typet_shorts.py data/projects/demo/shorts.py check
python3 scripts/typet_shorts.py data/projects/demo/shorts.py main
python3 scripts/typet_shorts.py data/projects/demo/shorts.py frames
python3 scripts/typet_shorts.py data/projects/demo/shorts.py seams
```

必要に応じて末尾にクリップIDを指定し、1本だけ確認・再書き出しする。検収シートは生成するだけでなく、AI自身が画像を確認する。

既存の動画を意図して再書き出す場合は `main --overwrite` を指定する。

## 4. 追加要望への対応

まず現在の計画で実現できるか検討する。

- 区間の追加・削除・並べ替え：採用区間を変更する。
- 画面比率・字幕の大きさ・字幕なし：出力・字幕設定を変更する。
- シンプルな短い動画を複数本：1本仕上げの計画を出力ごとに作る。
- 章別の書き出し：章ごとの区間で計画を分ける。
- BGM、複数素材の統合、合成など：現在の標準機能にはない。追加処理の方法、影響、作業範囲を説明し、必要な素材・条件を確認する。既存の仕様でできると装わない。

拡張する場合も、個別案件の素材や名前を共通コードへ埋め込まない。元の素材・編集計画・再現手順を残す。

## 5. 検収と納品

`references/editing-guide.md` の検収項目を確認する。長尺は冒頭だけでなく、中盤・末尾、全カット境界、字幕の長い箇所、画面が変わる箇所を対象にする。

納品時には次をまとめる。

- 完成ファイルの保存先、本数、実測の長さ・解像度。
- どの方針で何をカットしたか、字幕や音声の調整内容。
- 実施した検査と、未確認・判断が必要な箇所。
- ユーザーにお願いする最終確認：音声を含む通し再生と、固有名詞・意味の確認。

ローカルへの保存で制作を完了する。動画サイトへの投稿や外部共有は別途依頼があった場合に扱う。Gitへは制作データを追加しない。
